Como usar a página de vendas

Arquivos estáticos: sem Node, sem build e sem banco. Você troca a marca num arquivo só e sobe a pasta em qualquer hospedagem.

1. O que tem na pasta

ArquivoPara que serve
index.htmlA página. Os trechos que você pode mudar estão entre <!-- EDITÁVEL --> e <!-- FIM EDITÁVEL -->.
config.jsTudo o que muda de uma instalação para outra: marca, endereços, plano do botão, preços de reserva, contatos, Pixel e GA.
css/estilo.cssO visual. As cores ficam no topo do arquivo.
js/pagina.jsO comportamento (planos ao vivo, cores, utm, medição). Não precisa editar.
assets/Logo, mascote, ícones, imagem de compartilhamento e prints.
docs/O PRD da página. Não suba para a hospedagem.

2. Trocar a marca

No config.js

  • marca e assistente: os nomes que aparecem nos textos.
  • app: o endereço do sistema, por exemplo https://app.seudominio.com.br. Os botões levam para app/assinar/<código>, e o rodapé para app/termos e app/privacidade.
  • api: o endereço da API, se não for o mesmo do app (vazio = o mesmo do app; false = a página não chama o sistema).
  • planoBotao: o código do plano dos botões gerais. Está em Admin → Planos, no fim do link de venda.
  • precosReserva: o preço que aparece só se o sistema não responder. Mantenha igual ao do Admin.
  • whatsappSuporte, emailSuporte, empresa, cnpj e instagram: rodapé e FAQ. Campo vazio some da página.
  • fundador: a história do fundador. Com mostrar: false, ela some.

Nas imagens de assets/ (troque mantendo o nome)

ArquivoTamanho sugerido
logo.webpLogo para fundo claro, 96 px de altura
logo-escuro.webpLogo para fundo escuro (rodapé), 96 px de altura
mascote.webpÍcone ou mascote quadrado, 240 × 240
favicon.png e apple-touch-icon.png64 × 64 e 180 × 180
og-image.jpgPrévia do link no WhatsApp: 1200 × 630, até 300 KB

Se os logos tiverem outra proporção, ajuste width e height das tags <img class="logo"> no index.html.

No index.html

  • No topo: <title>, description e as tags og:. O Google e o WhatsApp leem esse texto antes do JavaScript, então troque o nome da marca aqui também.
  • og:url, og:image e canonical precisam do endereço completo da página publicada, como https://seudominio.com.br/assets/og-image.jpg.
  • Para trocar o nome em toda a página de uma vez, use "Localizar e substituir" no editor: troque "Dona Conta" pelo seu nome.

Cores

Com coresDaApi: true, a página usa as três cores de Admin → Marca. Se o sistema não responder, valem as de css/estilo.css (--cor-primaria, --cor-secundaria e --cor-destaque). Deixe as duas iguais.

Logo do Admin

Com logoDaApi: true, a página usa o logo de Admin → Marca. Só ligue se o arquivo enviado lá for leve (menos de 50 KB): o logo do Dona Conta hoje tem mais de 500 KB, e a página passaria de 1 MB no celular. Com false, valem os arquivos de assets/.

3. Prints reais

Enquanto não houver prints, a página mostra marcadores tracejados. Para trocar:

  1. Grave os prints com dados de exemplo (nunca dados de cliente).
  2. Salve em assets/prints/, em WebP, com estes nomes: 01-texto.webp, 02-audio.webp, 03-foto.webp, 04-pergunta.webp, 05-aviso-8h.webp, 06-resumo.webp (celular, 9:16) e 07-painel.webp (16:10).
  3. No config.js, troque para printsProntos: true.

Depoimentos: a seção 11 do index.html está desligada (dentro de um comentário). Ligue só com depoimentos reais, autorizados, com nome e cidade.

4. Antes de publicar

  • O sistema está na versão 1.12.0 ou mais nova. Antes dela, a API não deixa outra página ler planos e marca, e a página fica com os preços de reserva.
  • O plano do planoBotao está ativo e público em Admin → Planos.
  • O plano tem "Avisos de vencimento" e "Resumo periódico" ligados (seção "Envios automáticos aos grupos"). A página promete os dois. Plano novo nasce com eles desligados.
  • Os precosReserva batem com o Admin.
  • Os Termos e a Política de Privacidade estão publicados no app (/termos e /privacidade).
  • E-mail, WhatsApp e CNPJ são os de verdade.
  • A resposta de "Como cancelo?" no FAQ é o que o suporte faz de fato.

5. Publicar

Suba estes itens: index.html, config.js, css/, js/ e assets/. O COMO-USAR.html é opcional, e a pasta docs/ fica de fora.

Hostinger ou cPanel

  1. Abra o Gerenciador de Arquivos e entre em public_html (ou na pasta do domínio).
  2. Envie os arquivos e pastas acima. Dá para subir um .zip e usar "Extrair".
  3. Confira que o index.html ficou direto dentro de public_html, e não numa subpasta.
  4. Ative o SSL (HTTPS) do domínio no painel.

Netlify

  1. Entre em app.netlify.com/drop.
  2. Arraste a pasta da página (sem a pasta docs/). O site sobe na hora, com um endereço .netlify.app.
  3. Em Domain management, adicione seudominio.com.br e www e siga as instruções de DNS.
  4. Para atualizar, abra o site em Deploys e arraste a pasta de novo.

Cloudflare Pages

  1. No painel da Cloudflare, abra Workers & Pages → Criar → Pages → Enviar arquivos (Upload assets).
  2. Dê um nome ao projeto e arraste a pasta (sem docs/).
  3. Em Domínios personalizados, adicione seudominio.com.br e www.
  4. Para atualizar, crie uma nova implantação e envie a pasta de novo.

Domínio

seudominio.com.br e www apontam para a página. app.seudominio.com.br continua apontando para o sistema. Não mexa no registro do app. ao configurar a página: o login do app fica só nele.

6. Pixel da Meta e Google Analytics

  1. No config.js, preencha pixelMeta (só os números do ID) e/ou googleAnalytics (G-XXXXXXXXXX).
  2. Com um ID preenchido, a página carrega o script, registra a visita e mostra o aviso de cookies. Sem ID, nada é carregado.
  3. Todo clique num botão de assinatura dispara Lead no Pixel e generate_lead no GA, com o código do plano.

7. Campanhas (utm)

Use links como seudominio.com.br/?utm_source=instagram&utm_campaign=lancamento. A página leva todos os utm_* para os botões de assinatura, e o Admin mostra os cadastros e pagamentos de cada campanha nos números do link do plano.

8. Testar no computador

Abra a pasta com qualquer servidor local (por exemplo a extensão Live Server do VS Code) e confira:

  • os planos aparecem (do sistema ou, se ele não responder, os de reserva);
  • os botões levam para app/assinar/<código> com os utm_* do endereço;
  • a prévia do link fica certa, colando o endereço publicado numa conversa do WhatsApp.
